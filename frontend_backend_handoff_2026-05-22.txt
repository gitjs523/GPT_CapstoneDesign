3. Auth integration status
- Backend auth design:
  - accessToken: JWT, response body, frontend memory only
  - refreshToken: HttpOnly cookie named snow_refresh
  - refresh token rotation enabled
  - /api/auth/refresh requires credentials/cookie, not Authorization Bearer
- Frontend changes made:
  - Removed localStorage accessToken usage.
  - accessToken is stored in memory variable only.
  - login/signup fetch uses credentials: "include".
  - refresh uses POST /api/auth/refresh with credentials: "include".
  - authFetch attaches Authorization: Bearer <memory accessToken> to normal API requests.
  - 401 triggers refresh and retries the original request.
  - refreshPromise prevents duplicate simultaneous refresh calls.
  - JWT exp is decoded and refresh is scheduled 1 minute before expiry.
  - logout uses credentials: "include".
- Verified in browser:
  - login request URL: http://localhost:5500/api/auth/login
  - refresh request URL: http://localhost:5500/api/auth/refresh
  - refresh request has Cookie: snow_refresh=...
  - refresh response has Set-Cookie: snow_refresh=...
  - refresh response body contains accessToken
  - 새로고침 후 POST /api/auth/refresh, GET /api/users/me, GET /api/notebooks are normal.

6. Document upload/delete status
- Document upload request is sent to:
  POST /api/notebooks/{notebookId}/documents
- After upload, frontend polls:
  GET /api/notebooks/{notebookId}/documents/{documentId}/status
- If status is COMPLETED:
  - document stays and is marked analysis complete.
- If status is FAILED:
  - document now stays in UI and is marked "분석 실패".
  - Previously it disappeared; this was fixed.
- Current observed backend issue:
